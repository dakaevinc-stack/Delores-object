# Промпт агенту: заливка на плане (MeasureOverlay) — довести до приёмки

Скопируй этот файл целиком в чат агенту, когда заливка на DWG-плане снова «не та».

## Контекст продукта

- Сайт: https://deloresh.tech/ (VPS `94.242.58.24`, деплой: `npm run deploy:live -- root@94.242.58.24`).
- Объект: Олимпийская деревня, DWG «Заливки КДО» (`olympiyskaya-derevnya`).
- Пользователь смотрит **цветной PNG-план**. Клик в режиме **Измерить → Заливка** должен выделить **ровно ту цветную кляксу**, в которую ткнули.

## Что сейчас воспринимается как провал (не спорь с DOM Path)

Пользователь много раз присылал пустой `<svg class="_measureOverlay_*">`. Это **не доказательство**, что «ничего нет» и **не доказательство**, что «всё ок».

Провал = любое из:

1. Подсветка **не совпадает** с видимой цветной зоной (клин, треугольник, лужа, соседний цвет, пол-плана).
2. После клика **нет** явной цветной подсветки зоны (или мигает и пропадает).
3. Площадь в м² **не похожа** на размер кликнутой кляксы (часто ×10–×18 от LibreDWG HATCH).
4. Клик по серому/оливковому фону **съедает** огромный кусок плана.
5. Агент ответил «задеплоил, hard refresh», **не приложив** crop: PNG-зона + оверлей поверх.

Успех = на скрине/crop видно: кликнутая цветная область и подсветка **один в один** (пиксель в пиксель по силуэту).

## Железобетонные правила реализации

1. **Истина оверлея = flood-маска пикселей PNG** (`maskOverlay` / `paintRegionMaskOverlays`), не упрощённый полигон.
   - Path из 3–8 точек на диагональном коридоре = треугольник на пол-плана. Уже ломало прод.
   - `structuralZoneContour` / `softenContourForEditing` — только для ручек правки, **не** как единственная заливка.

2. **PNG раньше DXF HATCH.** LibreDWG hatch на «Заливках КДО» часто в 10–18× больше видимой зоны. Hatch — только fallback и только если IoU с PNG приемлемый.

3. **Площадь = `pixelCount / ppu²`**, пока пользователь не начал двигать вершины (тогда mask сбрасывается).

4. При `maskOverlay`: SVG-path **fill выключен** (обводка/номер можно). Заливка — canvas теми же coords, что `drawRasterPlanFrame`. Не полагайся только на SVG `<image href=dataURL>`.

5. `mix-blend-mode: multiply` на тёмном CAD — запрещён.

6. Перед «готово» обязательно на реальном Olympic PNG (`/tmp/olympic-fill.png` или актуальный preview с сервера):
   - розовый/зелёный компактный участок → подсветка = цвет;
   - тонкий диагональный коридор → нет triangle-wash;
   - олива/серый фон → отказ (spill), не пол-плана;
   - pan/zoom → маска прибита к растру.

7. Деплой только после зелёного `tsc -b` + тесты `dwgPngRegionPick` / raster measure; bump `public/sw.js` (shell/assets version). Без SW bump пользователь на кэше.

8. Не чини «только» цвет, opacity, long-press, тосты, подсказки — если маска/хит-тест не совпадают с PNG, проблема не решена.

## Обязательный артефакт перед ответом «готово»

Сохрани и опиши в ответе:

- `/tmp/olympic-fill-overlay-proof.png` (или аналог): crop зоны **с наложенной маской**.
- Коротко: seed `(x,y)`, `pixelCount`, `verts`, poly/mask ratio, `hasMask=true`.
- Версия SW на https://deloresh.tech/sw.js после деплоя.

Без crop — **нельзя** писать пользователю, что заливка починена.

## Как пользователь должен писать (для агента)

Принимай от пользователя **не DOM Path**, а:

1. Один скрин: план + то, что подсветилось после клика.
2. Одну фразу: «кликнул в [цвет] зону, а выделилось [что увидели]».
3. По желанию: объект + имя DWG + «Заливка» включена.

Если прислали только пустой svg MeasureOverlay — сам открой Olympic PNG, воспроизведи, приложи crop; не проси «ещё раз hard refresh» как единственный шаг.

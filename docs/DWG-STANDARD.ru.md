# Стандарт DWG в Deloresh Objects

Чтобы **любой сотрудник с доступом на запись** мог загрузить чертёж в **любой
объект** — и план, заливка, точки, отметки, зоны, расчёты работали **без ручной
доводки с программистом**.

Должность значения не имеет: порядок действий одинаковый для бригадира, ПТО,
директора и заместителя. Кому разрешено загружать — настраивается отдельно,
сам сценарий от этого не меняется.

---

## Что считается «готово»

После загрузки DWG система сама делает два превью на сервере:

| Превью | Зачем |
|--------|--------|
| **Цветной PNG-план** | Открытие, заливка, измерения по цвету, масштаб м² |
| **DXF** | Запасной режим, если PNG ещё не готов / не удался |

Функции на плане (заливка, точки, отметки, зоны) работают от **PNG**.
Пока PNG не `ready` — полноценной заливки нет.

**Готово** = в карточке чертежа статус «План готов» и «Открыть» показывает цветной план.

---

## Шаблон действий (всегда одинаковый)

1. Войти в аккаунт на **https://deloresh.tech** (обязательно под своим логином).
2. Объект → блок **Чертёж** → загрузить файл **`.dwg`** (до ~100 МБ).
3. Дождаться статуса:
   - «Готовим план…» — сервер рисует превью (обычно 1–5 мин, крупный файл дольше).
   - «План готов» — можно открывать.
4. Нажать **Открыть** → проверить зум двумя пальцами.
5. Проверить минимум:
   - **Измерить → Заливка** — клик по цветной зоне подсвечивает её.
   - **Точки** — длина/площадь считаются.
   - **Отметки / Маркер** — сохраняются после обновления страницы.
6. Если план пустой / ошибка — кнопка **«Обновить план»** (ещё раз собрать превью). Не грузить тот же файл заново без нужды.

Новый объект ничем не отличается: тот же DWG → тот же пайплайн.

---

## Новая версия чертежа: «Заменить», а не «загрузить рядом»

Проект изменился — в карточке чертежа нажать **«Заменить»** и выбрать новый `.dwg`.

Почему именно так:

- файл остаётся тем же самым, поэтому **отметки, заливки и расчёты никуда не деваются** — система сама переносит их на новый план;
- старый DWG и его превью **перезаписываются**, лишние копии на сервере не накапливаются;
- чертёж остаётся основным для объекта — карточка не перескочит на прошлую версию.

Если вместо «Заменить» загрузить второй файл, на объекте окажутся два чертежа,
а все отметки останутся на старом. Так делать не надо.

**Удаление** (кнопка «Удалить») убирает чертёж целиком: файл, оба превью и
отметки, сделанные на нём. Действие не отменяется — сначала «Заменить».

## Что делать / чего не делать

**Делать**
- Загружать только под логином (иначе файл останется только на телефоне).
- Один основной чертёж на объект помечать как главный (открывается с карточки).
- Новую версию проекта заводить через **«Заменить»**.

**Не делать**
- Не ждать программиста после каждой загрузки — сначала «Обновить план» и повторный вход.
- Не открывать DWG как «просто файл с диска» в AutoCAD-ожидании: в кабинете работает **серверный план**.
- Не грузить пакетом 5 огромных DWG сразу на слабом сервере — очередь по одному.
- Не удалять чертёж, если нужны сделанные на нём отметки.

## Формат и ограничения (технический минимум)

| Параметр | Норма |
|----------|--------|
| Формат | `.dwg` (предпочтительно не новее AutoCAD 2018–2020) |
| Размер | до 100 МБ; чем меньше — тем быстрее план |
| План на экране | PNG ~1500–2048 px по длинной стороне (быстрое открытие) |
| Масштаб м² | из метаданных PNG (`pixelsPerUnit`) — появляется вместе с планом |

Если DWG «битый» / без видимой геометрии для рендера — план может не построиться.
Тогда: «Обновить план» → если снова ошибка — упростить/пересохранить DWG в AutoCAD и загрузить снова.

## Для координатора полевого теста

Чек-лист на новом объекте (10 мин):

- [ ] Загрузка DWG под логином сотрудника (любая должность с доступом)
- [ ] Статус дошёл до «План готов» без вмешательства админа
- [ ] Открытие < ~10 с на нормальной сети (после ready)
- [ ] Заливка по цвету совпадает с зоной
- [ ] Отметка сохранилась на втором телефоне после обновления
- [ ] «Заменить» на новую версию — отметки остались на своих местах

Ссылка сотрудникам: этот файл + `docs/FIELD-TEST.ru.md`.

---

## Если снова «ломается» — не чинить вручную каждый файл

1. Сотрудник: **Обновить план**.
2. Админ: смотреть статус в API / манифесте (`pngPreviewStatus`), не переписывать заливку «под один объект».
3. Агенту в Cursor отдать промпт: `docs/AGENT-DWG-PIPELINE.prompt.ru.md`.

Правило продукта: пайплайн общий для всех объектов. Данные (DWG) разные — код один.

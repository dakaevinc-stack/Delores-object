# Как жить с сайтом без Cursor

Cursor — это просто программа для правок, как Word для текста.
**Сайт от неё не зависит.** Даже если Cursor завтра исчезнет —
сайт, сотрудники и сервер продолжат работать.

Ниже — что у вас есть и что делать руками.

---

## Что у вас есть (три коробки)

Представьте три коробки:

1. **Сейф с чертежами** — GitHub  
   Ссылка: https://github.com/dakaevinc-stack/Delores-object  
   Там лежит весь код. Это запасная копия.

2. **Папка на вашем Mac** — `Deloresh Objects`  
   Тут вы правите сайт, как файлы на рабочем столе.

3. **Настоящий сайт** — компьютер в интернете (сервер)  
   Адрес сейчас: **http://94.242.58.24/**  
   Сюда заходят сотрудники.

Правило простое:
- правите в папке на Mac →
- нажимаете одну команду →
- обновление улетает на настоящий сайт.

Запишите себе в заметки или парольник:

| Что | Зачем |
|-----|--------|
| Логин и пароль от GitHub | чтобы открыть «сейф» с кодом |

| Пароль/ключ от домена (когда купите) | чтобы привязать красивый адрес |

Без этих трёх вещей можно запутаться. С ними — спокойно.

## Если наймёте айтишников

Им не нужен Cursor. Дайте:

1. доступ к GitHub;
2. SSH к серверу (или сделайте деплой сами по команде ниже);
3. два файла из папки `docs/`:
   - **HANDOFF-TEAM.ru.md** — что за продукт и как устроен;
   - **FOR-DEVELOPERS.ru.md** — «хочу поменять X → открыть файл Y».

Попросите их перед правками гонять `npm run check`, а опасные зоны (чертёж DWG, удаление задач, логин) не переписывать с нуля без необходимости.

Стандарт загрузки DWG для сотрудников: **docs/DWG-STANDARD.ru.md**.
Промпт агенту по пайплайну чертежа: **docs/AGENT-DWG-PIPELINE.prompt.ru.md**.

## Как открыть проект без Cursor

1. Скачайте бесплатно **VS Code**: https://code.visualstudio.com/
2. Откройте папку `Deloresh Objects`
3. В меню Terminal → New Terminal (внизу появится чёрное окошко)

Если папки нет (новый компьютер):

```bash
git clone https://github.com/dakaevinc-stack/Delores-object.git
cd Delores-object
npm ci
```

Посмотреть сайт у себя на Mac (только вы видите):

```bash
npm run dev
```

Откройте в браузере: http://localhost:5173

## Как выложить обновление на настоящий сайт

Это главная кнопка. Делайте так каждый раз, когда закончили правки.

1. Откройте папку проекта на Mac.
2. Откройте Terminal (чёрное окошко).
3. Скопируйте и вставьте эту строку, нажмите Enter:

```bash
npm run deploy:live -- root@94.242.58.24
```

4. Подождите 1–3 минуты. Если в конце всё зелёное / без красных ошибок — готово.
5. Откройте на телефоне: http://94.242.58.24/  
   Обновите страницу (иногда дважды, или закройте вкладку и откройте снова).

Готово. Сотрудники видят новое.

### Если телефоны показывают старое

На сервере иногда «залипает» старая версия в кэше телефона.
Перед большим обновлением попросите кого-то, кто умеет, поднять номер версии
в файле `public/sw.js` (там слова вроде `deloresh-shell-v40` → `v41`).
Потом снова `npm run deploy:live ...`.

Для обычных дней проще первый способ: `deploy:live`.

## Домен deloresh.tech (важно!)

Ваш домен: **deloresh.tech**.

Сейчас он ещё смотрит на хостинг Reg.ru (`37.140.192.227`), а наш сайт —
на сервере `94.242.58.24`. Пока DNS не поменяете — сертификат HTTPS
выпустить нельзя (интернет не знает, что домен «наш»).

На сервере конфиг nginx под `deloresh.tech` уже подготовлен.
Остался один шаг у вас в кабинете Reg.ru.

### Шаг 1. Поменять DNS в Reg.ru (вы)

1. Зайдите на https://www.reg.ru/ → «Мои домены» → **deloresh.tech**.
2. Откройте **DNS-серверы и зона** / **Управление зоной**.
3. Сделайте так:

| Тип | Имя (хост) | Значение | Что сделать |
|-----|------------|----------|-------------|
| A | `@` или пусто | `94.242.58.24` | заменить старый IP |
| A | `www` | `94.242.58.24` | заменить старый IP |
| AAAA | `@` / `www` | — | **удалить** старые IPv6 от Reg.ru (или поставить `2a0c:16c3:500:a3::872b`) |

Почту Reg.ru (MX) трогать не нужно, если пользуетесь почтой на Reg.ru.

4. Сохраните. Подождите 10–60 минут (иногда до суток).

Проверка с Mac (должно показать `94.242.58.24`):

```bash
host deloresh.tech 8.8.8.8
```

### Шаг 2. Напишите мне «DNS готов»

Тогда на сервере выпустят бесплатный сертификат Let's Encrypt
(зелёный замочек) командой вроде:

```bash
certbot --nginx -d deloresh.tech -d www.deloresh.tech
```

После этого сотрудники открывают: **https://deloresh.tech/**

Старый адрес `http://94.242.58.24/` тоже продолжит работать.

## Бэкап (чтобы не потерять задачи и отчёты)

Код уже на GitHub.  
А вот **данные сотрудников** (задачи, формы, фото) лежат на сервере отдельно.

На сервере стоит **автоматический бэкап каждый день в 03:00**  
в `/var/backups/deloresh/` (хранятся 14 дней).

Проверить, что архивы появляются:

```bash
ssh root@94.242.58.24 'ls -lh /var/backups/deloresh/ | tail -5'
```

Скачать свежий архив к себе на Mac (подставьте дату из списка):

```bash
scp root@94.242.58.24:/var/backups/deloresh/deloresh-forms-2026-09-05.tgz ~/Desktop/
```

Если cron пропал (новый сервер) — один раз:

```bash
ssh root@94.242.58.24 'bash /home/deploy/Delores-object/scripts/deploy/install-backup-cron.sh'
```

(путь к репо на сервере может отличаться — тогда скопируйте `scripts/deploy/backup-site-forms.sh` и `install-backup-cron.sh` и запустите install).

Положите файл в папку «Бэкапы» — и спите спокойно.

## Если сайт «упал»

1. Откройте Terminal.
2. Зайдите на сервер:

```bash
ssh root@94.242.58.24
```

3. Проверьте:

```bash
systemctl status site-forms nginx
```

Если красное — попробуйте:

```bash
systemctl restart site-forms
```

4. Проверьте с Mac:

```bash
curl -fsS http://94.242.58.24/api/health
```

Должно ответить что-то вроде: `{"ok":true}`.

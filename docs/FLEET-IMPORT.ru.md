# Данные парка техники: откуда берутся и как обновить

Раздел «Спецтехника» показывает **только то, что есть в учётных таблицах**.
Ничего не досочиняется: если в таблице нет срока ОСАГО, в карточке будет
«Нет данных», а не зелёная галочка «в норме».

## Источники

| Файл | Что из него берём |
| --- | --- |
| `База ТС … .xlsx`, лист **БАЗА** | номер, VIN, модель, год, категория прав, СТС, ПТС, ОСАГО, диагностическая карта, собственник, лизинг, Виалон, ДУТ, транспондер, «Платон», тахограф, пропуск в Москву и зона въезда, примечания |
| тот же файл, лист **ремонты** | плановое ТО и показания счётчика на момент последнего ТО |
| тот же файл, лист **остатки ГСМ** | последние показания одометра/наработки, дата снятия, остаток топлива |
| тот же файл, лист **тралы** | длина, разрешённая масса, грузоподъёмность, число осей и состав сцепки |
| `Бортовой журнал.xlsx`, по листу на машину | ремонты: дата, документ, поставщик, вид работ, стоимость запчастей и работ |

Копии таблиц лежат в `scripts/data/fleet-imports/` — чтобы данные можно было
пересобрать в любой момент и проверить, откуда взялась каждая цифра.

## Как обновить, когда пришла новая версия таблиц

```bash
# 1. Заменить файлы в scripts/data/fleet-imports/ (имена оставить как есть
#    или поправить пути в package.json)

# 2. Посмотреть, что изменилось и нет ли новых проблем в данных
npm run fleet:report

# 3. Пересобрать src/data/fleet.imported.ts
npm run fleet:import

# 4. Сверить суммы с итогами самой таблицы
npm run fleet:verify

# 5. Проверить, что ни один госномер из таблиц не потерялся
npm run fleet:plates

# 6. Проверить проект целиком
npm run check
```

`src/data/fleet.imported.ts` — **сгенерированный** файл, руками его не правят:
следующий запуск импорта затрёт правки. Всё, что нужно поменять, меняется в
таблице.

## Как устроена сверка

Номера машин в таблицах меняются (перерегистрация) и написаны то кириллицей,
то латиницей, иногда с цифрой «0» вместо буквы «О». Поэтому:

- машины сверяются **по VIN**, номер — только как запасной вариант;
- совпадением считается либо полное равенство VIN, либо полные 17 знаков в
  начале (в таблице к некоторым VIN дописаны пометки вида «…(6)»). Короче
  нельзя: у КАМАЗов одной партии `XTC652005K1407605` и `XTC652005K1409565`
  совпадают первые 13 знаков, и по ним две разные машины склеились бы в одну;
- старые номера подхватываются автоматически из листов, где рядом с номером
  стоит VIN (`Н 481 ОУ 797` → `С 905 СС 99`, `77 РМ 6820` → `77 МХ 3409`);
- один случай пришлось указать вручную (`50 ХР 0737` → `77 МХ 0605`): в листе
  журнала по этому Case 570SТ нет ни номера, ни VIN. См. `MANUAL_PLATE_ALIASES`
  в `scripts/fleet-excel/build.mjs`.

Если импорт встретит что-то, чего не понимает — новый класс техники, лист
журнала без опознавательных знаков, запись о ремонте без даты, — он **упадёт с
ошибкой**, а не запишет приблизительные данные.

## Известные расхождения в самих таблицах

Это не ошибки импорта, а то, что стоит поправить в таблице:

1. **Сводка «Содержание» занижает расходы на 374 016,19 ₽.** По Sany 330
   (`77 РМ 7948`) в сводке стоит 36 426 ₽ — ссылка на первую строку листа
   вместо итога 410 442,19 ₽. Суммы по каждому листу сходятся до копейки,
   верна большая цифра.
2. **Невалидные даты выдачи СТС:** `14.14.2023` (`Е 344 ВК 977`),
   `19.19.2023` (`Н 421 УА 799`), `15.15.2024` (`77 МН 8101`). Месяц явно
   опечатка, а какой он на самом деле — из таблицы не видно, поэтому дата не
   импортирована, только номер документа.
3. **Шесть госномеров есть только во вспомогательных листах** («самосвалы»,
   «бирка ключи», «Лист1 (2)») — ни VIN, ни документов, ни ремонтов по ним
   нет. Заказчик подтвердил, что в парк их брать не нужно: `К 966 МУ 799` и
   `Р 177 ММ 797` (КАМАЗ 6520‑54 и 6520‑55), `У 526 МН 797` (Hyundai Sonata),
   `У 602 АЕ 977` (LADA 4X4), `Х 732 УН 777` (Range Rover). Шестой,
   `77 ММ 7058`, — тот же каток HD110 HAMM, что в реестре идёт под
   `77 МО 4698`; верный номер — из реестра.

   Решения записаны в `EXPECTED_OUTSIDE_FLEET` в
   `scripts/fleet-excel/audit-plates.mjs`, поэтому `npm run fleet:plates`
   докладывает только о **новых** номерах и падает, если такие появились.
4. **Прицеп 71491-0000010-01** (VIN `Х89714911L0FM4073`) в парке есть, но
   госномера у него нет — в примечании таблицы «ПТС не оформлен должным
   образом». В карточке вместо номерной таблички стоит «Без госномера», а
   опознаётся машина по VIN.
5. **Пять машин есть в бортовом журнале, но не в реестре ТС:** Toyota Camry
   `А 497 АС 799`, Geely Monjaro `Х 316 ОЕ 797`, Range Rover `Н 078 АМ 977`,
   Kia Sportage `Е 881 ТО 790`, Caterpillar PM620 `77 РВ 6778`. Они добавлены
   в парк по журналу, но документов (ОСАГО, ДК, СТС) по ним нет.
6. **Один КАМАЗ записан под двумя номерами:** в листе «ремонты» он идёт как
   `Н 443 АА 977`, в реестре — как `М 320 КО 977`. VIN один и тот же
   (`XTC652005K1407605`), это одна машина после перерегистрации.
7. **Опечатки в сводке «Содержание»** бортового журнала: `50 ХР 0605` и
   `77 РМ 3409` — смесь старого и нового номеров одной машины. На суммы не
   влияет, потому что ремонты берутся с листов, а не из сводки.
8. **Показания «ТО пройден» больше текущих** у `Н 421 УА 799` (30 247 против
   26 575) и `77 ММ 7012` (995 против 362,5) — данные импортированы как есть.

## Что в карточках техники намеренно пусто

Мощность, тип топлива, коробка, цвет, объём кузова, ответственный водитель и
его телефон в таблицах отсутствуют. Грузоподъёмность, масса, длина и число
осей есть только у двух полуприцепов — на листе «тралы». Раньше эти поля
заполнялись случайными значениями — теперь они пустые и заполняются вручную
в карточке (кнопка «Редактировать»). Пустое поле честнее выдуманного.

## Почему id техники привязан к госномеру

`id` собирается как `<класс>-<номер латиницей>`, например
`dump-trucks-k877ty799`. Раньше номер был позиционным (`dump-trucks-01`), и
любая вставка машины в середину списка «переклеивала» правки и отметки об
удалении на соседние машины. Номер меняется только при перерегистрации, и
такие случаи мы отслеживаем по VIN, поэтому привязка к нему устойчива.

Ключи старой схемы на устройствах чистит `src/lib/fleetDataMigration.ts` —
она же убирает тестовые записи аудита. Чистка идёт до обмена с сервером,
иначе устройство с устаревшим `localStorage` заливало бы мусор обратно.
